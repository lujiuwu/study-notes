**概念**

### webpack

**是什么**
* webpack是一个基于node.js开发的前端应用程序的静态模块打包工具，因此它的模块化也是common.js
* 它的功能是递归生成一个应用程序的依赖关系图，其中包含应用程序需要的每个模块，然后将这些模块打包成一个或多个bundle
* 它的作用是将原项目分散的代码和资源打包成更高效的，可以直接在浏览器中运行的文件bundle，在复杂大型项目中可以做到开发优化与性能优化的强大功能

**实际细节**
* 在项目中通过webpack.config.js进行配置
* 该配置文件包含的主要模块如下：
     1. entry入口文件（`在vue中默认为main.js`）
     2. output出口文件
     3. lorder
     4. plugins

#### loader

**作用**
* webpack只能直接处理JS格式的资源，任何非JS文件都必须经过loader处理转换为JS代码，比如图片视频等静态资源
**工作原理**
* 通过test正则表达式匹配需要处理的文件

**组成部分**
* 本质是一个node模块
* 该模块导出一个函数，函数的作用是接收源文件并返回对其处理后的结果
* 注意 -- 在返回处理结果上：
     1. 比起return，this.callback()是更规范的写法，不仅可以灵活的返回结果，还能为同步操作改成异步操作的可能性预留空间

**手写**
```js
module.exports = function(source){
  const result = source.replace('a','b')
  callback(null,result)
}
```

**导入**
```js
module : {
  rules : [{
    test:/\.js/
    use:[{
      loader:...
    }]
  }]
}
```

#### plugin

**作用**
* 在webpack编译过程的特定生命周期运行扩展逻辑

**自定义**

```js
class MyPlugin{
  apply(compiler){
    // compiler -- 通过该对象获取到webpack的钩子系统hooks
    // 具体的生命周期：run,compile,compilation,make,emit,done...
    // 注册行为：
    // tap 同步；tapAsync 异步回调风格 tapPromise promise风格
    compiler.hooks.done.tap('test',(stats)=>{
      // 中心逻辑
      // 异步操作必须执行
      cb()
    })
  }
}
```

**导入**

```js
plugins : [
  new MyPlugin()
]
```

#### webpack5 模块联邦

**是什么**
* 模块联邦允许一个JS应用动态加载另一个应用的代码，并在此过程中共享依赖，它的核心特点包括：
     1. 去中心化： 每个应用都可以作为主机或者远程
     2. 运行时共享
     3. 依赖共享
     4. 版本协商
* 该技术使得代码直接在项目间利用CDN直接共享，不再需要本地安装npm包
**实现**
* 模块联邦利用webpack5内置的`ModuleFederationPlugin`插件

**暴露与消费**
* 一个典型的模块联邦配置包含两部分：**暴露模块方**和**消费模块方**
* 暴露模块方配置exposes
* 消费模块方配置remotes

**重要参数**
1. name -- 当前应用名称，必须且全局唯一
2. remotes -- 用于将其他项目的name映射到当前项目
3. exposes -- 表示导出的模块，只有在此申明的模块才可以作为远程依赖被使用
4. shared -- 定义安装的依赖项，可以配置版本要求，单例模式等高级选项

### vite

**是什么**
是一个现代化的前端构建工具，它分为两部分：
* 基于原生ES Modules的开发服务器，提供极快的冷启动和热更新
* 生产构建方面，使用rollup进行代码打包，输出高度优化的静态资源

**出现的背景**
* vite的出现是为了解决传统构建工具在开发阶段的痛点：
     1. 缓慢的冷启动，因为webpack需要先打包整个应用才能启动开发服务器，项目越大耗时就越长
     2. 低效的热更新：修改文件后，webpack需要重新构建依赖图，导致更新速度随着项目的规模下降
     3. 复杂的配置：webpack的配置学习曲线陡峭

* 相比之下，vite利用浏览器原生支持ESM的特性，实现了`按需编译`，从根本上提升了开发体验

**作用和底层**
* 启动速度快，直接启动服务器，跳过了打包bundle的过程
  `1. 浏览器原生支持ESM，因此可以直接解析import/export语法，直接加载入口文件
  `2. 模块的加载由浏览器自身完成，无需提前打包`
* 按需请求模块
  `1. 只有当浏览器遇到import语法，才会向vite发起请求；除此之外的文件不做处理`
  `2. vite会拦截这些请求，实时编译当前文件，然后返回浏览器可执行的ESM格式代码`
* 更高效的热更新HMR实现
   `1. 当文件被修改时，服务器通过webSocket向浏览器发送HNR update事件 `
   `2. vite只会重新编译被修改的文件而非整个应用，并生成新的模块代码`
   `3. vite通过动态import重新请求被修改的模块；由于浏览器原生支持 ESM，新模块会直接替换旧模块，而无需刷新页面`

**与 Webpack 的区别：**

|特性|Vite|Webpack|
|---|---|---|
|**开发模式**|原生 ESM + 按需编译|打包所有代码再启动|
|**构建工具**|生产用 Rollup|自建打包机制|
|**性能**|开发阶段快，依赖 `esbuild`|大型项目构建慢|
|**配置**|开箱即用，插件少|插件生态丰富但配置复杂|
|**兼容性**|依赖现代浏览器 ESM|通过 Loader 支持旧环境|


## 总结

### 构建工具 & 打包工具

**为什么需要它们**
1. 浏览器只能直接运行JS代码和WEB标准资源，如HTML/CSS/静态资源；因此对于其他文件，例如TS风格语言和vue,react等单文件，就需要通过构建工具和打包工具进行转换和编译
2. 无构建工具的话，多个文件之间没有进行模块化管理，可能出现全局变量污染和CSS冲突等问题；因此需要构建工具进行npm包按需导入和CSS Moudle进行解决
3. 同时，对于大型复杂的前端应用程序，还存在着性能优化的需求；这些工具可以实现减少文件数量，压缩代码体积，Tree Shaking等功能


**构建工具基础**
* 构建工具是将前端源代码转换为`生产环境可运行代码`的自动化工具
* 它的功能包括：代码转译，预处理，代码优化和任务管理等等
* *常见工具：* vite,webpack,rollup

**打包工具基础**
* 打包工具是构建工具的一个子集；开发友好的代码转换为浏览器高效的运行时代码，同时解决模块化、性能、协作等工程问题
* 可以实现如下功能：
     1. 模块合并：将多个分散的JS/CSS文件合并为少数几个文件（减少HTTP请求）
     2. 依赖解析：处理import/export语句，确保模块正确加载
     3. 资源管理：将图片，字体等静态资源嵌入或生成引用路径
* *常见工具：* webpack,rollup

**何时可以不用**
* 纯展示无交互逻辑的静态页面

**两者关系**
* 构建工具和打包 工具都用于前端工程化流程；都可以处理代码转换
* 都支持开发模式和生产模式的区分
* 关键区别：
     1. 本质：构建工具专注于单个文件的优化转换；打包工具专注于多个文件和模块的整合
#### rollup

**概念** 
* rollup是一个现代JS模块打包工具
* 专注于将小代码块编译成更大更复杂的库或者应用

**特点**
* ESM优先：原生支持ESM 默认启动Tree Shaking
* 轻量高效
* 插件化

**实际应用**
* 库和框架的开发：vue和react等均用rollup打包
* 需要Tree Shaking的项目，即对代码体积敏感的场景
* ESM生态工具

**对比webpack**

| 特性               | Rollup     | Webpack      |
| ---------------- | ---------- | ------------ |
| **设计目标**         | 库/工具打包     | 应用打包（支持复杂功能） |
| **Tree Shaking** | 默认高效       | 需配置          |
| **输出代码**         | 更简洁，接近手写代码 | 包含运行时逻辑（稍冗余） |
| **开发体验**         | 配置简单，适合小规模 | 功能全面，适合大型项目  |

#### webpack

**概念**
* webpack是一个现代的前端项目静态模块打包工具，基于`node.js`开发；因此它的模块化是`common.js`
* 它的工作流程是从入口文件开始，构建整个应用的递归关系图，从而将各个模块打包成一个或多个浏览器可以直接执行的bundle文件
* 它的组成模块主要是：entry，output，loader，plugin

**对于静态模块的理解**
* 模块的依赖关系在代码构建阶段即可确定；打包时模块内容固定
##### loader

**概念&作用**
* webpack默认只可以处理JS格式代码，而对于其他语言和静态资源则需要下载对应loader才可以进行解析处理
* loader本质是一个函数；对于传入的soure源进行修改并返回修改结果


**手写**
```js
module.export = function(source){
  // 处理逻辑
  const res = ...
  return res
}
```

##### plugin

**概念&作用**
* webpack打包生成出口文件的流程中存在多个状态的生命周期钩子；比如`run, compile, done...`
* 而plugin的作用就是在特点的生命周期插入扩展逻辑，完成我们需要实现的逻辑
* plugin本质上是一个包含apply方法的自定义类

**手写**
```js
class MyPlugin{
  apply(compiler){
    // compiler用于获取我们需要的生命周期钩子
    compiler.hooks.done.tap('PluginTag',(stats)=>{
      // tap是插件注册的方式，有同步和异步两种类型
      // 异步必须执行的逻辑 -- cb()
    })
  }
}
```

##### 热更新

**概念**
* 当项目某一个模块更新时，工具构建而成的页面也需要对应着更新
* 这一流程的实现就是热更新

**本质**
* 当webpack的一个模块发送改变时，其文件及递归关系都会重新解析处理
* webpack计算差异并生成一个或多个补丁文件
* 通过webSocket向浏览器发送hash和ok事件；浏览器端的HMR Runtime会删除旧模块的缓存，并通过JSONP注入补丁文件

#### vite

**概念**
* vite是一个现代前端项目的构建工具
* 基于浏览器可以直接处理的ESM开发；生成环境使用的构建工具是rollup

**出现背景**
* vite的出现是为了解决此前传统构建打包工具的弊端
* 例如，相较于webpack，vite实现了以下优化：
     1. 跳过了打包流程，提高冷启动效率
     2. 按需加载资源
     3. 基于ESM的import，提高了热更新效率

**实现流程**
1. 启动服务器
     * vite启动服务器，但不打包任何代码，而是直接托管源代码
     * 浏览器加载入口文件
2. 按需请求模块
     * 只有当模块解析到import时才向vite服务器发送请求
     * vite拦截请求并实时编译，然后返回浏览器可执行的ESM格式代码
3. 依赖构建
     * 对于不是ESM格式的第三方依赖，vite在首次启动时用esbuild将其构建为ESM格式，并缓存到node_modules / .vite中
     * 当浏览器请求这些第三方缓存，实际加载的时预构建后的ESM版本
4. 热更新
     * 当文件被修改，vite只重新编译被修改的文件而非整个应用，并生成新的模块代码；此后服务器通过`WebSocket`向浏览器发送`HMR Update请求`
     * 浏览器接收信息后，通过动态import重新请求被修改的模块
     * 由于import的特性和浏览器原生支持ESM，新模块会直接替换旧模块，而无需刷新页面

**webpack 和 vite的区别**

|特性|Webpack|Vite|
|---|---|---|
|**开发模式原理**|打包所有代码再启动|原生 ESM 按需加载|
|**生产构建工具**|自建打包机制|Rollup|
|**HMR 速度**|较慢（需重建依赖图）|极快（单个文件编译）|
|**配置复杂度**|高（需配 Loader/Plugin）|低（开箱即用，支持 Rollup 插件）|
|**适用场景**|大型传统项目、需要深度定制|现代浏览器项目、追求开发速度|
### 脚手架

**概念&作用**
* 脚手架是一种自动化工具，用于快速生成项目的初始结构，配置文件，基础代码和依赖项
* 在前端开发中，脚手架变是一个`cli命令行工具`，例如：
     1. create-react-app
     2. vue-cli
     3. vite
* 作用包括：快速初始化项目，统一团队规范，集成最佳实践，支持定制化

**工作原理**
* 通过命令行进行交互式提问
* 根据用户选择从预制模版下载依赖文件并安装


#### vue-cli

**概念**
* 是vue.js官方提供的标准脚手架工具，用于快速初始化vue项目

**核心功能**
1. 一键生成项目结构
2. 支持交互式配置，如router vuex css预处理器等
3. 支持插件扩展功能
4. 支持打包优化（代码压缩，Tree Shaking）

**本质&特点**
* 基于webpack构建工具
* 配置可以通过vue.config.js修改
* 适用于构建vue2传统项目

### 包管理工具


**概念**
包管理工具是软件开发中用于自动化管理依赖项、库和模块的核心工具，它能帮助开发者高效处理代码复用、版本控制和环境配置等问题

**工具概览与核心特性对比**

|工具|核心特性|安装速度|磁盘占用|依赖隔离性|适用场景|
|---|---|---|---|---|---|
|**npm**|Node.js官方工具，生态最全|慢|高|无|常规Node.js项目|
|**yarn**|确定性安装+workspaces|较快|高|无|大型Monorepo项目|
|**pnpm**|硬链接+符号链接，节省空间|最快|极低|强|磁盘敏感/多项目环境|
|**cnpm**|淘宝镜像客户端，国内加速|快|高|无|国内网络环境|
|**npx**|临时执行工具，无需全局安装|-|-|-|一次性命令/版本测试|
