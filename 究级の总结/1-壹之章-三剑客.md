#### Web Storage 与 IndexedDB

##### IndexedDB

> **IndexedDB** 是一种基于浏览器的**纯客户端数据库**，用于在浏览器中存储大量结构化数据（如 JSON 对象、文件等）
> 
> 它类似于小型数据库，支持事务操作、索引查询和二进制数据存储，适合开发离线应用、缓存大量数据或实现本地数据持久化

**特点**
* 键值对存储，支持多种数据类型
* 所有操作都是异步的
* 大存储容量，通常支持50MB以上
* 支持同源政策：每个数据库绑定到特定域名，无法跨域访问
* 持久性：除非用户手动清除或通过代码删除，数据不会过期

**位置**
浏览器沙箱内，浏览器的本地文件系统中

##### Web Storage 与 IndexedDB

| 存储方式           | 存储位置                | 容量        | 数据类型     | 有效期       |
| -------------- | ------------------- | --------- | -------- | --------- |
| **IndexedDB**  | 浏览器本地文件系统           | 通常 > 50MB | 任意 JS 对象 | 永久（需手动删除） |
| localStorage   | 浏览器本地（文本形式）         | ~5-10MB   | 字符串      | 永久        |
| sessionStorage | 浏览器内存（当前会话）         | ~5-10MB   | 字符串      | 窗口关闭清除    |
| Cookie         | 浏览器本地 + 随 HTTP 请求发送 | ~4KB      | 字符串      | 可设置过期     |
| Web SQL        | 浏览器本地 SQL 数据库（已弃用）  | 通常 5MB    | 结构化数据    | 永久        |
**“何时应该使用 IndexedDB 而非 LocalStorage？”**

- **LocalStorage**：适合简单键值对存储（如用户偏好设置），数据量小。
- **IndexedDB**：适合大量结构化数据（如图库、离线应用），支持事务和索引。

#### 替换元素

由CSS2.1定义
* 替换元素是 CSS 布局中一类`特殊元素`，它们的内容由`外部资源`决定，具有`固有尺寸和特殊的布局行为`

**常见的替换元素**
* img图像 -- HTML IMG 元素的内容通常由其 src 属性指定的图像替换
* type="image"的input 表单输入
* textarea 多行文本输入
* select  下拉选择框
* video 视频
* audio 音频

##### 替换元素的核心特性

1. **内容由外部决定**：内容不受文档样式直接影响，而是由外部资源（如图片文件）或元素自身特性决定。
    
2. **固有尺寸（Intrinsic Dimensions）**：
    - 替换元素通常有自己固有的宽度、高度和宽高比
    - 例如：图片的尺寸由图片文件本身决定
        
3. **特殊的显示行为**：
    - 即使设置为 `display: inline`，也能设置宽度和高度
    - 垂直对齐方式（vertical-align）对其影响显著
        
4. **样式控制限制**：
    - 不能直接使用伪元素（::before, ::after）
    - 某些 CSS 属性对其无效

##### 替换元素在布局中的特殊表现

1. **宽高计算**：
    - 如果没有明确设置宽度或高度，将使用其固有尺寸
    - 如果只设置一个维度（如宽度），另一个维度（高度）会`按比例`缩放
        
2. **基线对齐**：
    - 替换元素的基线默认是其底部边缘
    - 这解释了为什么图片下方有时会有间隙

#### 选择器的优先级规则

**什么是优先级**
> 优先级是CSS中的一个匹配规则
* 浏览器根据该规则来判断哪些属性值与一个元素最为相关并进行应用
* 优先级是基于**不同种类选择器**组成的**匹配规则**，这是指：
  `对于同一个元素的不同种类选择器或声明语句，通过优先级的计算规则该元素应该采用哪些声明`
* 优先级的核心原则：**优先级高的样式会覆盖优先级低的样式**

**值得注意的是**
* 当同一个元素有`多个声明`的时候，优先级才会有意义
* 当优先级与多个CSS声明中任意一个声明的优先级相等的时候，CSS 中`最后的那个声明`将会被应用到元素上

**优先级高低**
* 优先级高低是由选择器类型所决定的
* 内联样式 > ID选择器 > 类/属性/伪类选择器 > 元素/伪元素选择器 > 通配符选择器与继承样式

**计算规则**

可以用 **四个数字（a, b, c, d）** 来表示一个选择器的优先级
分别对应内联样式、ID 选择器、类选择器等、元素选择器等的数量。

a. **内联样式**：a = 1, b = 0, c = 0, d = 0
b. **ID 选择器**：每出现一个 ID 选择器，b 加 1
c. **类选择器、属性选择器和伪类选择器**：每出现一个，c 加 1
d. **元素选择器和伪元素选择器**：每出现一个，d 加 1

比较两个选择器的优先级时，先比较 a，若 a 相同则比较 b，以此类推。

#### 伪元素与伪类

##### 是什么
* 伪元素和伪类是CSS3新增的特性
* 伪类：用于选择处于特定状态的元素或与文档树结构相关的元素
* 伪元素：用于创建文档中不存在的虚拟元素并为其应用样式

**伪类类型**
* 状态伪类（`基于用户交互的元素状态`）：:hover，:focus，:disabled，:active，:visited
* 结构伪类（`基于元素在文档树的位置`）：:first-child，:nth-child(even)，:empty
* 目标伪类（`基于URL中的锚点`）：:target
* 逻辑伪类（`用于组合多个选择器`）：:not，:is
* 表单相关伪类（`用于表单验证`）：:required，:valid

**笔试题 -- 链接伪类的正确书写顺序**
```css
a:link { color: blue; } /* 未访问的链接 */ 
a:visited { color: purple; } /* 已访问的链接 */ 
a:hover { color: red; } /* 鼠标悬停时 */ 
a:active { color: green; } /* 鼠标按下时 */
```

* 为什么需要规范顺序
  `确保每个状态的样式能正确覆盖前   
##### 区别
* 语法区别：伪类使用单冒号；伪元素使用双冒号
* DOM存在性：伪类选择现有元素；伪元素创建虚拟元素，这些元素不在HTML中，但渲染时存在
* 使用次数：一个选择器可以使用多个伪类；但一个选择器最多使用一个伪元素

#### 定位

**文档流**

元素默认按照**从左到右、从上到下**的顺序排列，块级元素独占一行，行内元素依次排列

**定位类型**
```css
.element {
  position: static;     /* 默认值，元素在文档流中正常布局 */
  position: relative;   /* 相对定位，相对于正常位置偏移 */
  position: absolute;   /* 绝对定位，相对于最近的已定位祖先元素 */
  position: fixed;      /* 固定定位，相对于浏览器视口 */
  position: sticky;     /* 粘性定位，滚动时固定在某个位置 */
}
```

**相对定位**
- 元素**仍占据原空间**，但可通过 `top/right/bottom/left` 相对于正常位置偏移。
- 可作为 `absolute` 子元素的定位参考点

**绝对定位**
- 元素**脱离文档流**，不占据原空间，位置相对于最近的**已定位祖先元素**（即 `position` 不为 `static` 的元素）。
- 若没有已定位祖先元素，则相对于 `<html>` 元素

**固定定位**
- 元素**脱离文档流**，相对于**浏览器视口**固定位置，滚动时不移动。
- 常用于导航栏、返回顶部按钮等。

**粘性定位**
- 元素**初始在文档流中正常布局**，当滚动到特定位置时，变为 `fixed` 定位。
- 必须指定 `top`、`right`、`bottom` 或 `left` 中的至少一个值

#### BFC

**是什么**
* BFC 即块级格式化上下文（Block Formatting Context）
* 是一个独立的渲染区域
* 规定了内部的块级元素如何布局，并且与外部元素相互隔离

**特性**
* 内部元素布局不受外部影响
* BFC之间的边距不会合并
* 浮动元素、绝对定位元素、行内块元素等会创建 BFC
* 清除浮动

**触发BFC的条件**
* 根元素HTML
* 浮动元素（float:left/right）
* 行内块元素
* 表格单元格
* 网格元素/弹性盒子元素
* 溢出overflow不为visible的元素

**应用场景**
* 清除浮动，防止高度塌陷：
  `浮动元素会脱离文档流，导致父元素高度塌陷。创建 BFC 可以包含浮动元素，解决高度塌陷问题`
* 防止边距合并

#### 浮动与清除浮动

**什么是浮动**
* 浮动是允许元素脱离原本文档流的技术
* 在CSS中设置float属性值为left/right

**浮动的特性**
- **脱离文档流**：浮动元素不再占据原来的空间，导致父元素高度塌陷。
- **行内元素表现**：浮动元素会使元素表现得像行内元素一样，在一行内排列，直到空间不足时换行
- **文本环绕**：浮动元素周围的文本会环绕它。
- **收缩包裹**：浮动元素的宽度会根据内容自动收缩，除非显式设置宽度。
  

**使用浮动的应用场景**
* 多列布局
* 图文混排，使文字环绕图片

**为什么要清除浮动**
* 浮动元素脱离文档流会导致父元素高度塌陷，影响页面布局
* 清除浮动就是为了解决这个问题，让父元素包含浮动元素的高度。

**清除浮动的方法**
* 使用clear属性
  `在浮动元素同级创建元素，给该元素设置clear属性`
  `clear 属性的值可以是 left、right、both 或 none，表示元素的哪一侧不允许有浮动元素`
* 创建BFC：`给父盒子设置overflow:auto/overflow:hidden`
* 使用伪元素 ：`通过:after 伪元素在父元素末尾添加一个清除浮动的元素。`

```html
        display: block;

    }

```

#### 动画animation与过渡transition

**是什么**
* 动画animation与过渡transition是实现页面动态效果的两大技术
* 它们都能让元素在状态变化时表现出平滑的视觉效果

##### animation

**定义**
动画是独立运行的周期性变化，不需要外部事件触发，通过`@keyframes`定义关键帧

**特点**
可以自定义多个中间状态，支持循环，反向播放等复杂效果

**核心属性**
- `animation-name`：指定 @keyframes 的名称。
- `animation-duration`：动画持续时间。
- `animation-timing-function`：速度曲线。
- `animation-iteration-count`：循环次数（如`infinite`）。
- `animation-direction`：播放方向（如`alternate`）。
- `animation-delay`：延迟时间。

```css
.box {
  width: 100px;
  height: 100px;
  background: red;
  animation: move 2s infinite alternate;
}

@keyframes move {
  0% { transform: translateX(0); }
  50% { background: blue; }
  100% { transform: translateX(200px); }
}
```

##### transition

**定义**
过渡是元素从一个状态到另一个状态的平滑变化过程，必须由事件（如 hover、click）或 JavaScript 触发

**特点**
只需定义开始和结束状态，中间状态由浏览器自动计算（补间动画）

**核心属性**
- `transition-property`：指定要过渡的 CSS 属性（如`width`、`opacity`）。
- `transition-duration`：过渡持续时间（如`1s`）。
- `transition-timing-function`：过渡速度曲线（如`ease`、`linear`）。
- `transition-delay`：过渡延迟时间。

```css
.box {
  width: 100px;
  height: 100px;
  background: red;
  transition: width 1s ease, background 0.5s;
}

.box:hover {
  width: 200px;
  background: blue;
}
```

##### 主要区别

| **对比项**   | **transition**          | **animation**                    |
| --------- | ----------------------- | -------------------------------- |
| **触发方式**  | 需要事件或 JavaScript 触发     | 自动运行，或通过 JavaScript 控制播放         |
| **关键帧定义** | 只能定义开始和结束状态             | 可以定义多个关键帧（0%~100%）               |
| **循环能力**  | 无法自动循环（需 JavaScript 辅助） | 支持无限循环（`infinite`）               |
| **方向控制**  | 只能正向过渡（状态切换时反向）         | 支持`normal`、`reverse`、`alternate` |
| **复杂运动**  | 适合简单状态变化（如 hover 效果）    | 适合复杂动画（如旋转、弹跳）                   |
| **性能**    | 通常较低（依赖状态变化）            | 通常较高（独立渲染层）                      |
- **ransition**：轻量级、事件驱动的状态变化，适合简单交互。
- **animation**：强大、独立的动画系统，适合复杂、周期性动效。

#### CSS Modules 与 CSS-in-JS

**概念**
在现代前端开发中，CSS Modules 和 CSS-in-JS 是两种`解决样式模块化和局部作用域的`主流方案

##### CSS Modules

> 通过文件名和路径生成独特的哈希前缀来隔离各个模块的方案
> 确保不同组件之间的类名不会冲突

**特点**
样式与组件文件强绑定，避免全局污染

##### CSS-in-JS

**核心思想**
* **样式即组件**：直接在 JavaScript/JSX 中编写样式，利用 JS 的动态能力
* **运行时隔离**：通过生成唯一类名或使用 Shadow DOM，实现样式隔离

##### 区别

| **对比项**  | **CSS Modules** | **CSS-in-JS**    |
| -------- | --------------- | ---------------- |
| **作用域**  | 编译时局部化，通过哈希类名   | 运行时局部化，通过动态生成    |
| **语法**   | 纯 CSS，支持预处理器    | JS 对象或模板字符串      |
| **动态样式** | 需通过 JS 变量控制     | 直接支持 JS 逻辑       |
| **构建产物** | 静态 CSS 文件       | 内联 style 标签或动态生成 |
| **性能**   | 加载性能好           | 运行时性能开销（可优化）     |
| **学习成本** | 低               | 较高               |
| **生态系统** | 与现有 CSS 工具兼容    | 提供完整的组件化解决方案     |

#### 自定义属性

**概念**
> 自定义属性也称CSS变量
> 是CSS3引入的一项技术，允许开发者在CSS中定义可复用的值

**定义**
* 使用--前缀定义变量，后跟值
* 作用域：在:root选择器下的变量全局可用；其余仅在当前元素及子元素中使用
```css
/* 全局变量 */
:root {
  --primary-color: #3498db;
  --border-radius: 4px;
}

/* 局部变量（仅在 .card 及其子元素中可用） */
.card {
  --card-padding: 16px;
}
```

**使用**
* 通过var( )函数引用变量
* var( )函数可以接收第二个参数作为默认值
```css
.button {
  background-color: var(--primary-color);
  border-radius: var(--border-radius);
  padding: var(--card-padding, 10px); /* 使用默认值 */
}
```

**特性**
* 自定义属性遵循 CSS 的级联规则，可以在不同作用域中被覆盖
* 自定义属性可以通过 JavaScript 动态修改，触发即时重绘
```css
:root {
  --theme-color: blue;
}

.button {
  background-color: var(--theme-color);
}
```
```javascript
// 通过 JS 修改变量
document.documentElement.style.setProperty('--theme-color', 'red');
```

* 子元素会继承父元素的自定义属性值，除非被覆盖

#### CSS预处理器

**概念**
* CSS 预处理器是一种将「扩展语法」转换为标准 CSS 的工具
* 它通过添加变量、嵌套、混合宏等特性，解决了原生 CSS 缺乏复用性、逻辑控制和结构性的问题

**解决问题**
* CSS缺乏变量系统，无法复用值的问题
* CSS无嵌套语法，需要重复书写父级选择器的问题
* CSS无法实现条件判断和循环的问题
* 在大型项目中样式难以组织与维护的问题

**核心功能**
- **变量与作用域**：定义可复用的值（颜色、字体大小等）
- **嵌套规则**：层级化书写选择器，更符合 HTML 结构
- **混合宏（Mixin）**：封装可复用的样式片段
- **函数与运算**：支持数学计算、字符串处理等
- **模块化导入**：拆分样式为多个文件并按需引入

**自定义属性与预处理器变量**

|**特性**|**CSS 自定义属性**|**预处理器变量（如 Sass）**|
|---|---|---|
|**作用域**|动态作用域，支持级联和继承|静态作用域，编译时确定|
|**动态更新**|支持（可通过 JS 实时修改）|不支持（编译后值固定）|
|**响应式设计**|适合（可在媒体查询中重新定义）|需手动编写多个变量|
|**与 JS 交互**|直接支持|需通过编译工具或额外配置|
|**计算能力**|仅支持简单计算（通过 calc ()）|支持复杂数学运算|


#### 浏览器前缀

**概念**
浏览器前缀（Vendor Prefixes）是浏览器厂商为尚未成为标准的 CSS 属性或特性添加的前缀
用于在标准未定稿前`试验新功能`
尽管随着 Web 标准化的推进，前缀的使用已逐渐减少，但在兼容旧版浏览器时仍需了解其机制

**基本形式**
- **语法**：在 CSS 属性或值前添加厂商标识符
- **主流前缀**：
    - `-webkit-`：Chrome、Safari、新 Edge
    - `-moz-`：Firefox
    - `-ms-`：Internet Explorer
    - `-o-`：Opera（旧版）
      
**为什么需要前缀**
- **实验性特性**：新 CSS 特性在标准化过程中可能存在多种实现方式
- **浏览器竞争**：厂商通过前缀抢先实现尚未标准化的功能
- **兼容性保障**：确保新特性在不同浏览器中正常工作

**前缀使用规则**
* 浏览器会优先使用支持的最后一个属性

**自动处理化工具**
* Autoprefixer

**注意**
* 由于标准化推进吗，越来越多的特性（如 `border-radius`、`transition`）已无需前缀
* 但是在一些实验特性，特定浏览器版本与小众浏览器的情况下，可能还需要使用
* 我们应该避免手动添加前缀，使用自动化工具：如 Autoprefixer，根据目标浏览器自动处理

#### 混合模式&严格模式

**概念**
* 在 CSS 中，混合模式和严格模式是浏览器渲染页面的两种不同模式
* 主要用于处理历史遗留的非标准 HTML 代码
* 这两种模式的存在源于 Web 发展过程中的兼容性需求

**历史背景**
- 在 W3C 制定 HTML 和 CSS 标准之前，各浏览器（如 Netscape 和 IE）有自己的非标准实现。
- 标准发布后，为了兼容旧网站，浏览器引入了两种渲染模式：
    - **严格模式**：按照 W3C 标准渲染页面
    - **混合模式**：以兼容旧浏览器的方式渲染页面，模拟 IE5.5 的非标准行为

**触发条件**
* 严格模式
```html
<!DOCTYPE html> <!-- HTML5标准DOCTYPE -->
```

* 混合模式
  1. 缺少DOCTYPE声明或使用不规范的DOCTYPE

**核心区别**
1. 盒模型计算方式
     * 严格模式下：元素宽度 = width + padding + border
     * 混合模式下：元素宽度 = width
2. 垂直居中行为
3. 行内元素高度
4. 表单元素尺寸
5. 空白边距处理

**检测和处理模式**
* 使用JS检测
```javascript
if (document.compatMode === 'CSS1Compat') {
  console.log('严格模式');
} else {
  console.log('混合模式');
}
```

#### 值和单位

##### 值

**什么是值**
CSS的规则包含声明，而声明就是由属性和值组成的
CSS的值是CSS属性的具体数据，用于描述该属性允许拥有何种类型的值，可以是`关键字，数字，长度，颜色，字符串，函数等`

**值的类型**
* 关键字：auto，none，inherit
* 数值：opacity透明度的数值；z-index的数值
* 长度值：数字+单位组成
* 颜色值：关键字；十六进制；RGB等
* 字符串值：图片的url路径
* 函数值：calc( )，var( )自定义属性等

##### 单位

**概念**
* 长度值是值类型的一种
* 而单位则是长度值的组成部分

**绝对长度单位**
* 这些单位和其他任何东西都没有关系
* 通常被认为是相同的大小

| 单位   | 名称     | 等价换算                    |
| ---- | ------ | ----------------------- |
| `cm` | 厘米     | 1cm = 37.8px            |
| `mm` | 毫米     | 1mm = 3.78px            |
| `Q`  | 四分之一毫米 | 1Q = 0.945px = 0.25mm   |
| `in` | 英寸     | 1in = 96px = 2.54cm     |
| `pc` | 派卡     | 1pc = 16px ≈ 0.4233cm   |
| `pt` | 磅      | 1pt = 4/3 px ≈ 0.3527mm |
| `px` | 像素     | 1px ≈ 0.2646mm          |

**相对长度单位**

* 相对单位则是相对于其他某些东西的，例如：
     1. em -- 相对于本元素的字体大小
     2. rem -- 相对于根元素html的字体大小
     3. vh & vw 相对于视口的高度和宽度
     4. lh -- 相对于本元素的行高
     5. rlh -- 相对于根元素html的行高
     6. 百分比 -- 相对于父元素的高度和宽度

#### 原型&原型链

**原型的概念**
* 每一个JavaScript对象 (null除外) 在创建的时候就会与之关联另一个对象
* 这个对象就是我们所说的原型，每一个对象都会从原型上"继承"属性和方法，通过__proto__属性获取对象的原型

* 特殊的是，对于JS函数而言（箭头函数除外），它具有一个特殊的属性prorotype指向自己的原型
* 已知我们可以使用new关键字调用函数，当该函数作为构造函数创建出一个新对象（即实例）后，会为其绑定一个新原型
* 这个新原型又可以通过constructor属性指向构造函数

* 我们可以得到这样的关系谱
```
function.prototype === obj.__proto__
obj.__proto__.constructor === function
```

**原型链的概念**

- 原型链是由多个 `[[Prototype]]` 连接而成的层级结构，当我们访问一个对象的属性时，JavaScript 会先在对象本身查找，若找不到则沿着原型链向上查找，直到找到该属性或到达链的末尾（`Object.prototype === null`）
- 可以说，其实原型链的本质就是实例属性的查找路径

* 原型链是实现隐式继承的方式


**通过原型给对象添加方法**
```js
func.prototype.getName = ()=>{...}
```
* 和直接在对象上定义的区别
  1. 原型上定义的方法是所有实例共享的
  2. 修改原型会影响所有已创建的实例

**原型污染**
* 原型污染是指攻击者通过修改 `Object.prototype` 或其他内置原型，注入恶意属性或方法的漏洞
* 由于所有对象都继承自 `Object.prototype`，这种修改会影响整个应用程序
* 针对这种可能发生的情况，我们的预防措施有：
     1. 避免使用不安全的库函数（如Object.assign( )）
     2. 使用Object.freeze( )函数防止原型被修改
     3. 使用更安全的解析方法，禁止用户输入直接操作原型

**原型与继承**
在ES6的class, extends关键字出现之前，社区出现了很多基于原型的继承方式：

* 原型链继承 -- 直接修改prototype
* 构造函数继承 -- 在子类构造函数中调用父类构造函数
* 组合继承 -- 通过原型链继承方法，通过构造函数继承属性
* 寄生组合继承 -- 优化组合继承，避免重复调用父类构造函数

#### 事件循环

* JS是单线程编程语言，一个主线程无法像其他多线程语言一样并发执行任务，为了避免队列阻塞的问题，我们将任务分为异步和同步
* 如何规范执行JS任务，就是event loop事件循环需要解决的问题
* 事件循环通过“非阻塞监听+队列调度”模拟了异步效果
* 同步和异步任务分别进入不同的执行"场所"：**同步的进入主线程，异步的进入Event Table，即事件表格并注册函数**
- 当满足触发回调的条件时，Event Table会将这个函数移入**Event Queue，即任务队列**（任务队列还分为宏任务与微任务）
- 主线程内的任务执行完毕为空，会去Event Queue读取对应的函数，先读取微任务队列，当微任务队列为空才可以读取宏任务队列，进而进入主线程执行
- 上述过程会不断重复，也就是常说的**Event Loop(事件循环)**。

值得注意的是，Event Loop 不是由 ECMAScript 标准（即 JavaScript 语言规范）定义的；而是由 **宿主环境**（如浏览器的 HTML Standard 或 Node.js 的 libuv）实现和管理的

**什么是Event Table** 
* Event Table 是宿主环境（如浏览器）管理异步任务的机制，不同异步任务对应不同的事件表
* 可以看作是一个**存储异步任务及其回调函数的映射表**，记录哪些事件（如定时器、网络请求、DOM事件等）完成后需要触发对应的回调

宿主环境（如浏览器引擎）的事件循环机制会持续检查主线程执行栈是否为空，这是事件循环的固有行为，而非单独的‘进程’。

**浏览器与Node事件循环的区别**
* 浏览器环境下，microtask 的任务队列是每个macrotask 执行完之后执行
* 而在 Node.js 中，microtask 会在事件循环的各个阶段之间执行，也就是一个阶段执行完毕，就会去执行 microtask 队列的任务

##### 迭代器对象

**容器对象**
* `容器对象（container object）`泛指用来存储一组数据元素的数据结构
* 例如数组、链表、栈与队列、哈希表、树结构、图等

**概念**
* 迭代器是使用户在容器对象上`遍历访问`的对象
* 使得用户无需关系对象的具体类型及内部实现细节

**JS中的迭代器**
* 在JS中，迭代器是一个具体的对象
* 如果我们想将一个对象变成迭代器，这个对需要符合`迭代器协议`

**迭代器协议**
* 迭代器协议定义了产生一系列值的标准方式；当值为有限个时，所有的值都被迭代完毕后，则会返回一个默认返回值
* 只是实现了一个拥有一下语义的next()方法，一个对象才能成为迭代器：
     1. 每次调用next()方法时，它包含两个属性：
     2. value -- 当前产生的值 ； done -- 表示当前是否所有的值都被迭代完成的布尔值

**迭代器发挥的作用**
* 迭代器内部需要维护一个指向当前位置的指针，不能单纯存储内容，而是需要变动指针索引
* 迭代器还需要具有通用性

##### 可迭代对象

**概念**
* MDN文档对于可迭代对象的说明：该对象必须实现`[Symbol.iterator]()`方法
* 可迭代对象需要实现的是`可迭代协议`

**迭代器对象和可迭代对象的区别**

| 特性   | 迭代器对象（Iterator Object）                                      | 可迭代对象（Iterable Object）                        |
| ---- | ----------------------------------------------------------- | --------------------------------------------- |
| 定义   | 一个实现了迭代器协议的对象，其包含 `next()` 方法，用于产生一系列值                      | 一个实现了可迭代协议的对象，可以使用 `for...of` 循环遍历            |
| 协议   | **迭代器协议**：必须实现 `next()` 方法，每次调用返回一个 `{ done, value }` 对象    | **可迭代协议**：必须实现 `Symbol.iterator` 方法，返回一个迭代器对象 |
| 目标用途 | 逐一产生数据值，直到 `done: true`，适合处理惰性计算和序列生成                       | 提供统一的方式遍历其所有元素，适合处理所有可被遍历的数据结构                |
| 实现要求 | 需要提供 `next()` 方法，该方法每次返回 `{ done: boolean, value: any }` 对象 | 需要实现 `Symbol.iterator` 方法，返回一个符合迭代器协议的对象      |
| 描述行为 | 倾向描述一个遍历访问的过程                                               | 倾向描述一个集合，它具备多个可以被遍历访问的对象                      |
| 实现结果 | 实现了遍历逻辑                                                     | 在迭代器对象的基础上提供了数据来源                             |
##### for..of...

**底层实现**
* 当我们使用for of时，JS引擎会自动调用可迭代对象的`[Symbol.iterator]()对象`，生成一个迭代器对象
* 然后，引擎使用这个迭代器对象的next()方法不断获取value，直到done属性为true表示遍历结束

**手动实现**
```js
function foo(obj){
  // 获取可迭代对象
  const it = obj[Symbol.iterator]()
  // 遍历
  while(!it.done){
    console.log(it.value)
    it = it.next()
  }
}
```

#### 生成器

##### 基础理论

**概念**
* 生成器是ES6引入的一种`特殊函数类型`
* 它的作用是让我们在函数执行过程中暂停和恢复执行
* 生成器可以看作是一个生成迭代器的工厂函数，可以根据需求逐步生成值，而不是一次性返回所偶结果

**生成器函数和普通函数的区别**
* 首先，生成器函数需要在function的后面加一个符号：*
- 其次，生成器函数可以通过`yield关键字`来控制函数的执行流程
- 最后，生成器函数的返回值是一个`Generator（生成器）`
- 生成器对象可以调用next( )方法，说明它是一个特殊迭代器

```js
function* g(){
  console.log('start')

  // 在需要暂停的地方添加yield关键字
  yield 'pause'
  console.log('continue')
}
```

**生成器函数的调用方式**
* 初始化：调用生成器函数并不会立即执行函数，而是返回一个生成器对象
* 通过调用这一`可迭代的`生成器对象的`next()`方法；生成器函数开始执行直到遇到第一个yield表达式，此时暂停执行并返回yield的值；以此循环往复到函数结束

##### 关于yield

**概念**
* 可以理解为每个阶段的return关键字；默认返回值是undefined，可以自定义为多种类型的表达式expression
* 其内部实际操作：
```js
// rv是传递给生成器的next()方法的可选值
const [rv] = yiled [expression]
// 默认执行并返回结果；以恢复后续执行
it.next(rv)
```

**yield的双向通信功能**

- **作为输出：** `yield` 后面的值会被 `next()` 方法返回给外部
- **作为输入：** `yield` 表达式的值取决于下一次调用 `next(value)` 时传入的参数
```js
function* generator(){
  console.log('第一次执行')
  const res = yield '第一次暂停'
  console.log('第一次接收',res)
  console.log('第二次恢复执行')
  yield '第二次暂停'
  console.log('第三次恢复执行；执行完毕')
}
const it = generator()
```

**错位双向传递**

> 我们注意到这种 **错位（staggered）** 的现象，即输入的值似乎总是滞后于输出一个阶段

* 生成器函数和调用者是交替执行的，它们轮流控制着程序的执行权
```js
function* generator() {
  // 执行权在生成器函数
  console.log('第一次执行')
  // yield关键字触发暂停 -- 执行权交给调用者
  const res = yield '第一次暂停'
  
  // 调用者如果执行next函数 -- 执行权交给生成器函数
  console.log('第一次接收', res)
  console.log('第二次恢复执行')
  
  // 执行权交给调用者
  yield '第二次暂停'
  
  // 执行权交给生成器函数
  console.log('第三次恢复执行；执行完毕')
}

const it = generator()
it.next()
it.next('res1')
it.next()
```

> 如果没有错位传递，会出现什么情况？

* 输入和输出在同一阶段，生成器函数需要在未暂停的情况下接收外部输入，这在 `单线程的 JavaScrip`t 中是无法实现的
* 如果尝试在同一阶段同时输入和输出，会出现以下问题：
     1. 控制权的归属问题
     2. 执行顺序的混乱
     3. 数据传递的矛盾

#### TS -- 接口&类型别名

**接口 interface**
* 接口是定义对象类型的一种方式，它只会为类型命名，不会创建新类型
```ts
interface People{
  name:string
}
const p1:People = {
  name:'name'
}
```

* 特点
  1. 只能定义对象，函数和类的结构
  2. 支持继承 extends关键字
  3. 同名接口会自动合并属性

**类型别名**
* 类型别名可以定义任意类型，包括基本类型、联合类型、交叉类型等
```typescript
// 基本类型别名
type Name = string;

// 对象类型别名
type Point = {
  x: number;
  y: number;
};

// 联合类型
type ID = string | number;

// 交叉类型
type Student = Person & {
  grade: number;
};

// 函数类型
type AddFunction = (a: number, b: number) => number;
```

* 特点
  1. 可以定义任何类型
  2. 使用typeof以获取实例类型
  3. 不支持合并

**interface与type的区别**

（1）`type`能够表示非对象类型，而`interface`只能表示对象类型（包括数组、函数等）。

（2）`interface`可以继承其他类型，`type`不支持继承。

（3）同名`interface`会自动合并，同名`type`则会报错。也就是说，TypeScript 不允许使用`type`多次定义同一个类型

（4）`interface`不能包含属性映射（mapping），`type`可以

（5）`this`关键字只能用于`interface`

（6）type 可以扩展原始数据类型，interface 不行

（7）`interface`无法表达某些复杂类型（比如交叉类型和联合类型），但是`type`可以

#### TS -- 泛型

**概念**
TS的泛型，允许开发者在定义函数，类和接口时不预先指定具体类型，而是在使用时才确定
这一特性使得代码具有更高的复用性和类型安全性

**语法**
* 泛型通过类型变量来实现，通常使用 T,U,K 来表示

```typescript
// 函数接受一个参数，并返回相同类型的值
function identity<T>(arg: T): T {
  return arg;
}

// 使用泛型函数
const num = identity<number>(10); // 指定类型参数
const str = identity("hello");    // 类型参数自动推断

// 泛型接口
interface Box<T> {
  value: T;
}

const numberBox: Box<number> = { value: 42 };
const stringBox: Box<string> = { value: "text" };
```

**泛型默认值**

> 在使用泛型的地方，可以设置一个类型的默认值

```ts
function<T=string>(str:T):T{
  return T+1
}
```

```ts
class Person<T=string,V=number>{
  name:T,
  age:V
}
```



**泛型约束**
有时需要限制泛型类型必须具有某些属性，可以使用 `extends` 关键字实现约束
```typescript
// 约束 T 必须有 length 属性
function getLength<T extends { length: number }>(arg: T): number {
  return arg.length;
}

getLength("hello");    // ✅ 字符串有 length 属性
getLength([1, 2, 3]);  // ✅ 数组有 length 属性
getLength(123);        // ❌ 数字没有 length 属性
```


#### TS -- 装饰器
> 装饰器（Decorator）是一种语法结构，用来在定义时修改类（class）的行为

**在语法上，装饰器有如下几个特征**

（1）第一个字符（或者说前缀）是`@`，后面是一个表达式。

（2）`@`后面的表达式，必须是一个函数（或者执行后可以得到一个函数）。

（3）这个函数接受所修饰对象的一些相关值作为参数。

（4）这个函数要么不返回值，要么返回一个新对象取代所修饰的目标对象

**简单装饰器实现**
* 必须使用装饰器的参数，否则会报错
```ts
function simpleDecorator(target: any, context: any) {
  console.log("hi, this is " + target);
  return target;
}

@simpleDecorator
class A {} // "hi, this is class A {}"
```

#### 跨域

**什么是同源政策**
* 如果两个页面的`协议`，`域名`和`端口`都相同，则两个页面具有**相同的源**
* 同源策略是**浏览器提供**的一个**安全功能**，即非同源的两个网站之间不能进行资源交互
     1. 无法读取非同源网页的 `Cookie`、`LocalStorage` 和 `IndexedDB`
     2. 无法接触非同源网页的 `DOM`
     3. 无法向非同源地址发送 `AJAX` 请求

**跨域**
与同源相反的情况，就称为跨域，即协议，端口或域名有一个不一样

**出现跨域的根本原因**
* 浏览器的`同源策略`不允许非同源的 URL 之间进行资源的交互

**浏览器允许发起跨域请求，但是跨域请求回来的数据，会被浏览器拦截，无法被页面获取到**

**如何实现跨域数据请求**
实现跨域数据请求方法有很多，其中最主要的三种解决方案分别是 JSONP 和 CORS 和 Nginx反向代理

**cors**
CORS是一个W3C标准，全称是"跨域资源共享"（Cross-origin resource sharing）
它允许浏览器向跨源服务器，发出`XMLHttpRequest`请求，从而克服了AJAX只能同源使用的限制
它将请求分为两类：简单请求与非简单请求
* 基本流程 -- 对于简单请求，浏览器直接发出CORS请求。具体来说，就是在头信息之中，增加一个`Origin`字段。
* `Origin`字段用来说明，本次请求`来自哪个源（协议 + 域名 + 端口）`
* 服务器根据这个值，决定是否同意这次请求
* 关于cookie : 上面说到，CORS请求默认不发送Cookie和HTTP认证信息。如果要把Cookie发到服务器，一方面要服务器同意，指定`Access-Control-Allow-Credentials`字段

**JSONP**
* 全称是JSON With Padding，是JSON的一种使用模式
* 可用于解决主流浏览器的**跨域数据访问**的问题
* 兼容性好；在请求完毕后可以通过调用`callback`的方式回传结果
* 原理：简单来说，定义一个回调函数；使用没有同源政策限制的script发送请求并接受服务端响应数据

**CORS与JSONP的区别**
* CORS比JSONP更加强大
* JSONP只能处理GET请求
* JSONP的**兼容性更好**，在更加古老的浏览器中都可以运行
  
#### 沙箱

> `沙箱(Sandbox)`，就是让你的程序跑在一个隔离的环境下，不对外界的其他程序造成影响
> 过创建类似沙盒的独立作业环境，在其内部运行的程序并不能对硬盘产生永久性的影响

Chrome浏览器打开的每个页面就是一个沙箱，保证**彼此独立互不影响**

**为什么需要？**
* 沙箱设计的目的是为了让`不可信的代码`运行在一定的环境中，从而`限制`这些代码`访问隔离区之外的资源`

比如像JSONP可能导致的CSRF攻击和XSS漏洞，我们就可以使用沙箱进行解决

**实现**
* 简陋的 -- with + new Function
* 常用的 -- 使用iframe标签 + sandbox属性

**沙箱逃逸**

**沙箱于作者而言是一种安全策略，但于使用者而言可能是一种束缚**
脑洞大开的开发者们尝试用各种方式摆脱这种束缚，也称之为`沙箱逃逸`
因此一个沙箱程序最大的挑战就是如何检测并禁止这些预期之外的程序执行

#### async & defer

* 这两个属性都是用于控制脚本的加载与执行时机

**区别**

|**属性**|加载方式|执行时机|顺序保证|适用场景|
|---|---|---|---|---|
|**无**|阻塞 HTML 解析|立即执行（加载完成后）|按标签顺序|需要立即执行的脚本|
|**defer**|异步加载|HTML 解析完成后（DOMContentLoaded 前）|按标签顺序|需要 DOM 结构的脚本（如操作 DOM 的库）|
|**async**|异步加载|加载完成后立即执行|**不保证顺序**|独立功能的脚本（如广告、分析）|
defer -- 脚本异步加载，HTML解析完成后顺序执行；DOM就绪
async -- 脚本异步加载，加载完毕后立即执行，可能中断HTML解析；不保证顺序
- **defer**：**异步加载，顺序执行，DOM 就绪后触发**，适合需要操作 DOM 的脚本。
- **async**：**异步加载，不保证顺序，加载完成立即执行**，适合独立功能的第三方脚本。

### Promise & async await

#### Promise

**概念**
* Promise是JS中处理异步操作的对象，表示一个异步操作的状态及其结果值
* 状态：pending fulfilled rejected
* 特点：状态一旦改变就不可逆；可以通过then和catch方法链式调用

**出现背景**
* 在此之前，我们想要完成一个异步操作，通常选用的方法是利用回调函数处理异步结果，这样的方式虽然简单，但并不适用于复杂的异步流程控制：
     1. 如果回调的嵌套层级过深，就会导致回调地狱的问题，难以阅读和维护
     2. 而且这个过程没有明确的规范，导致获取结果的方式和顺序都有所不同，不利于团队协作的标准化
* 为此，我们需要更好的异步解决方案

**Promise的优势**
* 封装好了所有的处理与回调，标准化API接口，开发者无需关注内部原理，开箱即用
* 链式调用扁平化代码

##### 状态

* 在通过new创建Promise对象时，我们需要传入一个回调函数，我们称之为executor，这是承诺开始的地方
  `在该阶段，Promise的状态为待定`

* 这个回调函数会立即执行，并且给其传入另外两个回调函数resolve和reject
* 做出状态改变决定的方法是通过excutor提供的参数


- 当我们调用resolve回调函数时，会执行Promise对象的then方法传入的回调函数；执行完毕后Promise对象状态变为`fulfilled 兑现`
- 当我们调用reject回调函数时，会执行Promise对象的catch方法传入的回调函数；执行完毕后Promise对象状态变为`rejected 拒绝`
  `执行任一回调函数，该Promise的状态都锁死，不可改变`

##### 链式调用

**概念**
* 链式调用时一种连续处理多个异步操作，每个操作都可以基于前一个操作结果的方式

**基础**
* 链式调用的基础是Promise的实例方法会返回一个新的Promise对象

##### 类方法/静态方法

**静态方法不依赖于具体的Promise实例**
* 因此非常适合封装各种工具函数

**resolve**
* 在Promise的executor回调中，resolve方法可以传递成功信息value，事实上该方法还能单独从Promise中调用，即作为类方法调用
* 该方法的执行结果根据传值类型有所不同：

```js
// 当传入的对象为Promise或其子类：value.constructor === Promise
// 返回结果res === value
const p1 = Promise.resolve(new Promise((resolve,reject)=>resolve()))

// 当传入的对象为其他情况
// 创建一个值相同的新promise对象；且状态为fulfilled
const p2 = Promise.resolve(1)
// 相当于如下代码：
const p2 = new Promise((resolve)=>resolve(1))
```

**reject**

* **无论 `reason` 是什么类型的值**（包括 Promise、thenable，或任何其他类型），`Promise.reject()` 都会返回一个状态为 rejected 的新 Promise，并且这个 Promise 的拒绝理由将是传入的 `reason`
* `Promise.reject()` 总是简单地把任何传入的值当做拒绝的理由，并且不进行任何额外的处理或状态检查

**all**
* 用于将多个Promise实例包装成一个新的Promise实例
* 有当所有输入的 Promise 实例都变为 `fulfilled` 状态时，返回的 Promise 才会变为 `fulfilled` 状态，此时输入的所有 Promise 的结果组成一个数组传递给 `fulfilled` 回调
* 如果任意一个输入的 Promise 实例变为 `rejected` 状态，`Promise.all()` 返回的 Promise 实例立即变为 `rejected` 状态，且第一个被 `reject` 的实例的返回值传递给 `rejected` 回调

**allSettled**
- 该方法会在所有的Promise都有结果（settled），无论是fulfilled，还是rejected时，才会有最终的状态
- 并且这个Promise的结果`一定是fulfilled的`
- allSettled的结果在一个数组的基础上，继续存放着每一个Promise的结果，并且是对应每一个对象；格式如下：
```js
// all promise res： [  
//   { status: 'rejected', reason: 'p1 reject error' },  
//   { status: 'fulfilled', value: 'p2 resolve' },  
//   { status: 'fulfilled', value: 'p3 resolve' }  
// ]
```


**any**
- any方法会等到一个fulfilled状态，才会决定新Promise的状态
    
- 如果**所有的Promise都是reject**的，那么**也会等到所有的Promise都变成rejected状态**

**race**
* **race是竞技、竞赛**的意思，表示**多个Promise相互竞争**，谁**先有结果，那么就使用谁的结果**
* 自定义实现直接使用forEach

##### 对象方法/实例方法

**then**
* 最多接收两个参数：onFulfilled 与 onRejected
* then方法可以被多次调用，链式调用和拆分的链式调用
* then方法的返回值形式：
     1. 普通值 被包装为一个新的Promise对象
     2. Promise
     3. thenable对象

**catch**
- catch方法具备两种调用形式，隐式与显式
  1. 隐式调用：then方法第二参数
  2. 显示调用：then方法之后接着链式调用catch方法
* 关于规范
  1. Promise A+规范规定写法为隐式；甚至是没有catch这个方法
  2. 但ES6中为了使阅读性提供了第二种写法；`相当于then的语法糖`

**then阶段一返回错误信息到阶段的方式**
1. reject调用
2. throw new Error 抛出异常

**堆栈跟踪（Stack Trace）**
* 是一个调试工具
* 终端显示的错误信息主要来自于`堆栈跟踪`
* 这部分信息提供了错误发生时的`具体位置`和`调用栈路径`；让开发者能够快速定位问题原因，理解错误发生时程序的状态和上下文
* 关于丰富度
     1. 在executor阶段抛出的整个调用栈
     2. 而在then方法中抛出的错误信息就只有我们所抛出的部分

**finally**
* 是ES9新增的一个特性，表示无论Promise对象变成任何状态，最终都会被执行的代码
- 该`finally规范`在Promise A+规范中也是没有的，和catch方法一样，依旧是ES6及之后由ECMA实现Promise时所扩展的特殊方法

##### 拒绝捕获错误

**概念**

* 我们如果将then方法与catch方法分开调用，这两次调用是不会相互影响，而是互为独立
* 一旦相互独立，它们都是残缺版的处理方式
* 此时就会出现**无法处理的异常情况**
- 如果不为 `Promise` 提供正确的处理回调，任何由 `reject`或`resolve` 产生的错误都不会被处理，继续向下传播，最终导致**运行时错误**从而**异常退出**Node运行程序

##### thenable

**概念**
* thenable 对象指的是任何具有 `then` 方法的对象
* thenable 可以被视为 Promise 的一个子集或简化版本

**与Promise**
* thenable对象可以被Promise机制识别，并被处理为Promise，这是它的作用，也是Promise识别其对象中自己实现then方法的原因
* 因此开发者可以创建自定义的 thenable 对象，而不必严格继承或依赖于特定的 Promise 类

##### 手写

**类方法**
```js
// all
Promise.prototype._all = function(promises){
  return new Promise((resolve,reject)=>{
    const arr = []
    promises.forEach(promise=>{
      promise.then(res=>{
        arr.push(res)
        if(arr.length === promises.length) resolve(arr)
      }).catch(err=>{
        reject(err)
      })
    })
  })
}
// allSettled
Promise.prototype._allSettled = function(promises){
  return new Promise((resolve,reject)=>{
    const arr = []
    promises.forEach(promise=>{
      promise.then(res=>{
        arr.push({status:'fulfilled',value:res})
      }).catch(err=>{
        arr.push({status:'rejected',reason:err})
      }).finally(
        ()=>{if(arr.length === promises.length) resolve(arr)}
      )
    })
  })
}
// any
Promise.prototype._any = function(promises){
  return new Promise((resolve,reject)=>{
    const arr = []
    promises.forEach(promise=>{
      promise.then(res=>{
        resolve(res)
      }).catch(err=>{
        arr.push(err)
        if(arr.length === promises.length) reject(arr)
      })
    })
  })
}
// race
Promise.prototype._race = function(promises){
  return new Promis((resolve)=>{
    promises.forEach(promise=>{
      promise.then(resolve,reject)
    })
  }
)
}
```

#### async & await

**概念**
* async声明一个异步函数，返回值会自动包装成Promise
* await暂停异步函数的执行，等待Promise解决

* 两者本质是 **Generator + Promise 的语法糖**

* 两者必须搭配使用：
     1. await的关键作用是暂停当前函数的执行以等待Promise的处理，这种暂停能力需要async函数的特殊环境支持
     2. 普通函数没有暂停机制，直接使用await会报语法错误

**如果单独使用**
* 如果单独使用async -- 函数会返回Promise但无法暂停执行
* 如果单独使用await -- 缺乏async的上下文，引擎不知道如何暂停和恢复执行


**本质上来说，async和await是promise的语法糖，让异步代码看上去像同步代码**

**示例代码**
```js
async function getData(){
  try {
    return await axios.get(...)
  }catch(err) {
    throw err
  }
}
```

**与Promise的区别**

|特性|Promise|async/await|
|---|---|---|
|**表现形式**|链式调用（`.then()`）|同步式写法|
|**错误处理**|`.catch()` 或链式末尾捕获|`try/catch` 块|
|**代码结构**|横向扩展（可能产生回调地狱）|纵向扩展（类似同步代码）|
|**执行控制**|手动管理异步流程|自动暂停/恢复函数执行|
|**返回值**|必须显式返回 Promise|隐式返回 Promise|
**与Promise的转换**

```js
// Promise写法
function p1(){
  return new getData().then(res=>{
    transForm(res)
  }).catch(err=>{
    handleError(err)
  })
  })
}
// async / await写法
function p2(){
  try{
    const res = await getData()
    return transForm(res)
  }catch(err){
    handleError(err)
  }
}
```


### axios

axios是一个基于promise的HTTP客户端，主要用于浏览器与nodejs环境

**解决的HTTP请求的痛点**
* Axios 提供了统一的 API，可以在**浏览器**和**Node.js**中使用相同的代码发送 HTTP 请求，避免了不同环境下 API 不一致的问题
* Axios 使用 Promise 处理异步请求，避免了传统回调地狱的问题，使代码更易读和维护
* Axios 支持拦截器，可以在请求发送前或响应返回后统一处理逻辑，例如添加认证头、日志记录、错误处理等
* Axios 支持取消请求，避免不必要的网络请求（例如组件卸载时取消未完成的请求）
* Axios 会自动将响应数据转换为 JSON 对象，无需手动解析

**axios二次封装**
- **统一配置**：设置基础 URL、超时时间等全局配置。
     1. 使用axios.create创建自定义实例
     2. 配置baseURL，timeout等
- **拦截器**：添加请求拦截器（如添加认证头）和响应拦截器（如错误处理）
     1. 配置interceptors.request / response
     2. 统一错误处理逻辑
- **简化 API**：提供简洁的请求方法（如 `get`, `post`）。
- **统一错误处理**：集中处理网络错误和业务错误。
- **取消请求**：支持请求取消功能。

```javascript

// 创建 axios 实例
const service = axios.create({
  baseURL: import.meta.env.VITE_API_BASE_URL, // 基础 API URL，从环境变量获取
  timeout: 10000, // 请求超时时间
  withCredentials: true, // 跨域请求时携带 cookie
});

// 请求拦截器
service.interceptors.request.use(
  (config) => {
    // 在发送请求前做些什么
    const token = localStorage.getItem('token');
    if (token) {
      // 为请求添加认证头
      config.headers.Authorization = `Bearer ${token}`;
    }
    return config;
  },
  (error) => {
    // 处理请求错误
    console.error('请求错误:', error);
    return Promise.reject(error);
  }
);

// 响应拦截器
service.interceptors.response.use(
  (response) => {
    // 对响应数据做些什么
    const res = response.data;
    
    // 根据业务状态码处理响应
    if (res.code !== 200) {
      ElMessage.error(res.message || '请求失败');
      
      // 特殊状态码处理（如未登录）
      if (res.code === 401) {
        // 跳转到登录页
        window.location.href = '/login';
      }
      
      return Promise.reject(new Error(res.message || '请求失败'));
    }
    
    return res.data; // 直接返回业务数据
  },
  (error) => {
    // 处理响应错误
    const { response } = error;
    
    if (response) {
      // 服务器返回错误状态码
      const errorMsg = `HTTP错误 ${response.status}: ${response.statusText}`;
      ElMessage.error(errorMsg);
      console.error(errorMsg, response.data);
    } else if (error.message.includes('timeout')) {
      // 请求超时
      ElMessage.error('请求超时，请稍后重试');
    } else if (error.message === 'Network Error') {
      // 网络错误
      ElMessage.error('网络连接失败，请检查网络');
    }
    
    return Promise.reject(error);
  }
);
```
